## Evidence and architectural decision

The NEXUS run reports 83,147,858 input and 488,121 output tokens over 18,573.671 seconds. Its outer controller accounts for 48,088,320 input tokens. Cached input and reasoning output are subsets. This is one run affected by infrastructure and external interference; it does not measure Yoke-core-only savings.

Existing Yoke has a deterministic loop, structured events, bounded context packets, write-scope scheduling, routing budgets, and attempt-local gate snapshots. Extend these existing seams. A new orchestrator framework or wholesale loop rewrite would duplicate functioning mechanisms and increase risk. Merely reducing checks would undermine the objective. The chosen approach preserves acceptance and adds bounded handoff, reliable contracts, and measured reuse.

## Required outcomes

1. External controllers can wait for meaningful loop state changes without model-based polling. A bounded CLI result includes state, progress, relevant failure/decision, and a resume cursor; timeout remains an explicit outcome.
2. Worker/planner/reviewer packets contain scoped contracts, file ownership, relevant invariants, and bounded feedback. Required acceptance must never be silently truncated. Long reference material is content-addressed and retrieved deterministically.
3. Approved requirements map to executable criterion IDs. Missing mappings, stale objective bindings, invalid references, and incomplete completion are rejected mechanically. Legacy projects remain loadable; draft output and documentation expose the stronger contract.
4. Reviews explicitly examine invariants, preserved capabilities, boundary behavior, and test adequacy. Structural coverage does not claim semantic completeness. Independent review and protected acceptance remain distinct from action approval.
5. Windows execution resolves absolute cwd and uses a process-local bounded PATH preserving required tools and the current worktree's executable resolution. Infrastructure failures are classified before expensive calls where possible.
6. Infrastructure attempts and implementation attempts have separate bounded accounting. Historical usage/failure evidence is retained. Missing usage cannot justify granting a free semantic attempt.
7. Verification reuse is conservative: identical command, workspace, contract, environment, and phase only; failures and mutating commands are never reusable. Integration/release boundaries still receive required fresh checks.
8. Planning uses the smallest coherent decomposition with explicit shared ownership. Parallel execution follows real dependency/write boundaries rather than a forced story count.
9. Usage records retain cached/fresh input and reasoning subsets where reported, with missing fields explicit. Synthetic regression benchmarks measure handoff/context/verification work; no unsupported provider-cost or whole-run saving claim.
10. Version, manifests, changelog, docs, package checks, full tests, independent review, and an install smoke produce a concrete 1.25.0 deliverable.

## Non-goals

No NEXUS app fixes, model/effort downgrade, removed acceptance gates, automatic mutation of user configuration, shared mutable node_modules, broad new framework, unrelated dashboard rewrite, or public savings percentage inferred from synthetic tests.

## Interfaces and integration

- Loop waiting is a CLI/API over existing reporter state and filesystem notifications; it never starts an agent. It must close watchers/timers on success, timeout, abort, and errors. Capture startup/read races and atomic status replacement.
- Context packing extends existing deterministic retrieval and prompt builders. Acceptance and current story scope are binding; excerpts are marked with source identity and location.
- Requirements live alongside PRD state and are validated whenever an active ledger is present. Source identity and criterion references are explicit. Planner-generated documents cannot silently redefine the original objective.
- Execution environment normalization is shared by provider/preflight and verification process launch. It only changes child environments.
- Routing keeps atomic reservation semantics, crash safety, and bounded restarts. Infrastructure records remain visible even when they do not consume the semantic limit.
- Verification cache is invocation-local and explicit about identity/reuse eligibility. It never substitutes for a required independent integrated verification.
- Existing scheduling is retained; planning instructions and requirement ownership validation close preventable gaps.

## Definition of Done

Each outcome has a failing behavioral regression before implementation and passing focused tests afterward. Existing tests are not weakened to accommodate implementation. Full Windows test suite, typecheck/build, docs consistency, canon validation, package dry-run, audit, and tarball install/CLI smoke are executed. Independent review reports issues; important findings are resolved and retested. Release documentation distinguishes local measurements from unmeasured model-run savings, lists compatibility/default changes, and does not claim public release completion without publication evidence.

## Risks and mitigations

- Context reduction can omit requirements: keep acceptance/invariants mandatory and hash/reference only secondary material.
- Cache reuse can accept stale state: identity includes environment/phase; mutation/failure disables reuse; integrated boundaries stay fresh.
- Infrastructure classification can hide real implementation failures: classification uses structured evidence and preserves ambiguous attempts as charged.
- Requirements mapping can be formally complete but semantically wrong: reviewer sees original objective and invariants; coverage is not a quality verdict.
- Waiting can miss filesystem events: initial read, subscribe, second read, atomic replacement handling, and explicit timeout are tested.
- Global version/worktree changes: use only the owned checkout and version-local tarball; preserve concurrent work.
