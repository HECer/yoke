# Yoke 1.0 — hardening, Codex parity, and parallel delivery

**Status:** Approved design, ready for implementation planning  
**Release target:** `@hecer/yoke@1.0.0`

## Goal

Make Yoke's cross-agent promise true at the integration, execution, and evidence layers:
Codex receives the same reusable methodology as Claude; reviews produce a mechanical verdict;
autonomous execution is safe by default; commits have an explicit human identity; parallel work
lands through a verified merge queue; and published claims are generated from reproducible data.

## Compatibility contract

- Existing `.yoke/config.yaml` files remain valid. New fields are optional and receive safe defaults.
- The CLI keeps all existing commands and exit codes. New commands and flags are additive.
- `--unsafe` is an explicit per-run escalation. Existing configurations do not silently gain broader permissions.
- Existing PRDs without `needs`, `area`, or `agent` behave as serial, dependency-free backlogs.
- Serial execution remains the default. Parallel execution requires `--parallel=N`, where `N > 1`.
- A 1.0 migration note documents every behavior whose default becomes safer.

## Native Codex integration

The Codex retrofit planner copies every canon skill to `.agents/skills/<id>/SKILL.md`, the native
repository skill location. It generates a directly usable, trusted-project `.codex/config.toml`
instead of describing it as a global snippet. Codex receives an RTK `PreToolUse` hook through
`.codex/hooks.json`; `RTK.md` remains as readable fallback guidance and `AGENTS.md` imports it.

Yoke also ships a Codex-compatible plugin bundle containing the canon skills, hook definition, and
MCP declarations. Repository-local custom agents provide narrow implementer, reviewer, security,
and documentation roles. These are conveniences over the same canon, not a second source of truth.

Generated artifacts remain non-destructive: Yoke backs up overwritten files, merges supported
configuration, and preserves project-owned instruction blocks.

## Mechanical review verdicts

`--review` resolves the first available agent that differs from the implementer. If no independent
agent is available, the command fails before implementation unless the caller explicitly requests
`--allow-self-review`.

Reviewers write a versioned JSON verdict to a Yoke-owned temporary path:

```json
{
  "schemaVersion": 1,
  "verdict": "approve",
  "summary": "All acceptance criteria are covered.",
  "findings": []
}
```

Yoke validates the file, rejects missing or malformed verdicts, and blocks on any `reject` verdict.
The process exit code remains execution telemetry only. Standalone `yoke review` uses the same
protocol and prints findings in human or JSON form.

## Safe runner profiles

- `safe` is the default and uses each CLI's non-interactive workspace-write mode without granting
  arbitrary host access where the provider supports it.
- `unsafe` uses full-bypass flags and requires `--unsafe` or `runner.permissions: unsafe`.
- `read-only` is available for reviewer and audit roles.

The effective runner, model when reported, permission profile, working directory, and network mode
are emitted at run start. Yoke refuses incompatible combinations instead of silently escalating.
Worktree isolation is automatic for parallel runs and recommended for serial unsafe runs.

## Human-owned commits

Configuration accepts:

```yaml
commit:
  authorName: HECer
  authorEmail: hec_er@web.de
  allowCoAuthors: false
```

When absent, Yoke resolves the repository's Git identity and fails clearly if no name or email is
available. Each commit passes the identity directly to Git. Yoke never adds AI co-author trailers;
canon skills respect `allowCoAuthors: false`, which is the default.

## Dependency-aware parallel loop

PRD stories gain optional `needs: string[]`, `area: string`, and
`agent: claude | codex | gemini`. `yoke prd check` rejects missing dependencies,
self-dependencies, and cycles. The scheduler runs only ready stories and never runs two stories
from the same area concurrently.

Workers claim stories through project-scoped claim files containing dispatcher ID, PID, base commit,
and timestamp. Each worker runs implement, verify, performance, and independent review gates in its
own worktree. Successful workers enter a FIFO merge queue. The integrator rebases onto current HEAD,
re-runs verification when HEAD moved, fast-forward integrates, updates context and PRD state, and
commits with the configured human identity. Conflicts or post-rebase failures return the story to the
open set; they never mark it passed.

The dispatcher owns the existing loop lock. Cleanup removes only project-owned claims and processes.
`--parallel=1` is behaviorally equivalent to the serial isolated loop.

## Security gate

`yoke audit [dir]` provides exit-code and JSON contracts for dependency auditing, conservative
tracked-secret detection, sensitive changed-file checks, and an optional project security command.
Findings have stable rule IDs and severities. Suppressions require a versioned reason and exact rule
ID. The loop can run audit after verify and before review.

## Cross-runner telemetry and benchmarks

Provider adapters own invocation, structured event parsing, usage/model extraction, permissions, and
review transport. Claude keeps stream-json; Codex and Gemini use supported JSON modes where available
and explicitly report unavailable usage otherwise.

Benchmarks record fixture version, runner/model, permission profile, outcome, wall time, token usage,
iterations, review verdict, conflicts, and final tests. Authenticated live runs stay opt-in and public
CI uses deterministic fake CLIs. Committed results state sample size and missing credentials honestly.

## CI, dependencies, and release truth

Vitest and its Vite/PostCSS chain are upgraded until development and production audits are clean. CI
adds deterministic source checks, build/tests, canon validation, audit policy, documentation drift
checks, `npm pack --dry-run`, and a tarball install smoke test.

A metadata script derives package version, skill count, test count, and supported agents for README
badges and prose. The canon version follows the package version and the `0.0.0` fallback is removed.
CHANGELOG and migration documentation explain 1.0 behavior.

## Repository hygiene

Cleanup detects stale Yoke and provider worktrees but does not remove provider-owned worktrees without
an explicit flag. Open roadmap work is mirrored into a versioned backlog or GitHub issues so it is
executable rather than living only in README prose.

## Error handling and observability

All machine interfaces are schema-versioned. Missing or malformed verdicts, unavailable CLIs,
unsupported safe modes, stale claims, conflicts, and audit findings preserve evidence and produce
distinct reasons. NDJSON includes worker, queue, review, security, cost, and commit-identity events.
No failure path marks a story passed before integrated-tree gates and the commit succeed.

## Testing strategy

Implementation follows red-green-refactor. Tests cover schema compatibility, generated artifacts,
review parsing and selection, safe invocations, Git identity, DAG validation, scheduling, claims,
merge retries, audit rules, telemetry, metadata generation, and CLI exit codes. Temporary Git repos
exercise commits, worktrees, conflicts, and authorship. Optional authenticated smoke scripts cover
real CLIs without blocking public CI.

Final verification runs the complete test matrix, build, canon validation, audit, documentation check,
package dry-run, and fresh install smoke test from the generated tarball.
