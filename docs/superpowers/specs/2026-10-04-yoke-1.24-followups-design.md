## Decision

Implement the remaining contracts at boundaries Yoke actually owns. Prefer benchmark-owned npm provisioning over a universal autonomous installer or a receipt-only claim that unmanaged dependencies are coherent. Add typed failure observations at known production boundaries rather than guessing category from error text or a nonzero exit. Reuse the controlled comparison harness and preserve acceptance tests instead of building another scheduler.

Existing user approval of E7/E8/E9 and the explicit continuation instruction authorize these bounded changes. Original NEXUS evidence and the dirty main checkout remain untouched. No model/effort downgrade or narrower quality gate is used to meet an estimated runtime.

## F1: Benchmark dependency setup

- Replace the full-repository benchmark's shared node_modules junction with project-local npm setup using its own package.json/package-lock.json. No install before inputs are validated; setup failure stops before model dispatch.
- Successful setup writes a local ignored receipt bound to package/lock bytes, Node/platform/architecture, npm version and exact installer arguments. Reuse requires matching inputs and a present local install; changed/deleted lockfiles and failed setup never yield reuse success. Receipts are readiness evidence, not an attestation that every installed byte remains unchanged.
- Conventional writable caches remain local; a package-download cache may be shared. Reject linked receipt/input/cache escapes and preserve source/lock bytes. No dependency installer is introduced into Yoke core; unmanaged readiness remains unverified.
- At the known npm boundary, classify structured offline cache miss, network, authentication, timeout and spawn causes; unsupported/script/unknown failures remain explicit unknown. No secret messages or unlimited retries. Record observed setup duration and reuse/install state separately from model time.
- RED/GREEN behavior tests cover successful install/reuse, each invalidation, failed receipts, safe paths, bounded failure classification and no model dispatch on setup failure.

## F2: Durable production failure observations

- Carry optional category plus bounded cause codes from explicit execution/verifier/provider/completion/integration boundaries. Timeout/spawn/capture/storage are infrastructure; invalid observation/evidence is observer; verified semantic assertion metadata may be product. Arbitrary exit/throw and absent metadata remain unknown; cancellation stays distinct.
- Completion and recovery failures are durably observable even without an active story attempt. Preserve failure identity through parent/attempt/recovery views and count one failure once.
- Archive allowlists retain only safe structured fields. Never parse arbitrary summaries into categories or copy secrets/stdout into new telemetry. Preserve original exceptions, salvaged usage, candidate retention, HEAD/source checks and best-effort telemetry behavior.
- Behavior tests traverse real emitters through archived local reports, including serial/parallel completion, provider failure, known verifier failure, proof/recovery causes, explicit product metadata, cancellation, deduplication and legacy events.

## F3: Controlled measurements and populated layout

- Copy NEXUS to a new isolated fixture without its macOS node_modules or broken Git metadata; provision platform-correct dependencies without modifying the original. Rerun immutable populated desktop acceptance (seven incidents, reachable actions, timestamped events and contained panels), plus the original required quality gates. Require strict port and confirmed source/build identity. Infrastructure failures stay failed/unavailable, never passes.
- Measure three paired samples per genuinely defined fresh-download-cache/warm-download-cache setup condition, alternating order and keeping lock inputs constant. Do not label repeated projects as cold/warm provider caches.
- Run at least three alternating-order baseline/candidate Codex CLI pairs on identical immutable acceptance and declared model/effort/startup/permission policy. Remove API-key overrides from child environments without exposing values; retain existing ChatGPT authentication. Record actual reported model, usage coverage, wall/setup/acceptance time, failures and empirical ranges. Do not claim full NEXUS/general superiority from a smaller fixture; full-product coverage or provider limits remain explicit if unavailable.
- Keep measured snapshots immutable and read-only during source gates. Report unknown costs, guardian/approval waits and cache state. No fabricated coverage, timing or efficiency percentage.
