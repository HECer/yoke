# Yoke 1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Yoke 1.0 with native Codex parity, safe and observable runners, mechanical reviews, human-owned commits, a security gate, dependency-aware parallel execution, and reproducible release claims.

**Architecture:** Keep the existing canon → retrofit → loop layers, but split provider-specific execution from loop policy. Add small schema-validated modules for review verdicts, commit identity, audits, PRD dependencies, and parallel scheduling; the CLI composes them without duplicating policy.

**Tech Stack:** TypeScript ESM, Node.js 20+, Zod, YAML, Vitest, Git worktrees, npm packaging, provider CLIs.
