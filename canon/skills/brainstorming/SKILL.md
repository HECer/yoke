# Resolve the design uncertainty

Read the relevant project context and existing implementation. State the desired outcome, constraints, and the specific unknown that could change the solution. Reuse decisions already accepted in the conversation or project plan.

Compare two or three feasible approaches only when a real tradeoff exists. Recommend one using user value, implementation cost, operating cost, compatibility, and reversibility. A small, specified change can proceed with a few sentences of reasoning.

Ask a focused question only if the answer materially changes product behavior, risk, external cost, data ownership, or an irreversible choice. Resolve routine implementation details yourself. Do not require repeated approval of an already authorized plan.

Record durable decisions in the project's existing plan or decision log. Include the acceptance evidence and relevant failure cases. Draw a diagram or prototype only when it resolves uncertainty more clearly than prose. Do not start a separate visualization server merely because the task involves UI.

Continue into the authorized implementation once the decision is clear. Load a planning skill only if dependencies and scope need a written execution plan; do not require an automatic chain of methodology skills.
