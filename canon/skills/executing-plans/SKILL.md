# Execute the accepted plan

Read the plan, current repository state, relevant instructions, and completed evidence. Confirm what remains. Reuse the existing task branch or create isolation if concurrent or unrelated changes require it; do not force a worktree for every small task.

Carry out authorized steps in dependency order. Resolve routine details from the code and established conventions. If evidence invalidates the plan, record the change and ask only about material scope, risk, or irreversible decisions. A failing test normally calls for diagnosis and repair, not an immediate handoff to the user.

Use only available tools and one controller. A Yoke worker executes its assigned scope without nested agents. Independent tasks can be delegated by the host when their benefit exceeds coordination and model cost; share the configured budget.

Run meaningful focused checks during implementation and required integrated checks before acceptance. Report changed files, current evidence, and remaining risks. Complete the already authorized PR or other handoff without another methodology cycle or fixed menu. Do not restart capped work, weaken acceptance, discard unrelated changes, or claim unfinished checks passed.
